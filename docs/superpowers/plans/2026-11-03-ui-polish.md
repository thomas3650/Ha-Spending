# UI polish from the 0.10.0 user test – implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps are test-first.

**Goal:** the [UI polish spec](../specs/2026-11-03-ui-polish.md), in one PR that closes #50, #77, #78, #82, #85, #86,
#87, #88, #89, #90, #91, #92, #94, #95 and #98.

**Architecture:** the server reads a list's pages at most 4 at a time and keeps the span-free parts of an answer per
day, under their own timeout. It writes every log line through one module with a time. The page changes in its
components and models: the placeholder's box count, the right card's head row, the split and the detail, the search
hint, the amount and date input, the filter menu, and small texts. No new route, option or dependency.

**Tech stack:** TypeScript; Hono on Node; Lit with Vitest, happy-dom and Testing Library.

**Spec:** [`docs/superpowers/specs/2026-11-03-ui-polish.md`](../specs/2026-11-03-ui-polish.md). Every task reads its
sections there; the plan does not repeat them.

## Global constraints

- `CLAUDE.md` hard rules 5 to 8: tests by role, accessible name and text; made-up data; English code; Danish only in
  `addon/web/src/i18n/da.ts`; comments only for why; docs change with the code.
- In `addon/`: `npm run lint && npm test && npm run build` pass before every commit; `node scripts/check-links.mjs` in
  the repo root.
- No write to Firefly III. No new dependency, route or option. Tests and subagents never touch `local/` or `.env`.
- New `da` keys, exactly: `amountInvalid: "Skriv et beløb som 1.000,50"`, `dateInvalid: "Skriv en dato som 31.12.2026"`,
  `dateFuture: "Datoen er efter i dag"`, `dateOrder: "Til er før Fra"`, `filterSearch: "Søg i filtre"`,
  `noFilterHits: "Ingen filtre passer"`, `tinyChange: "under 0,1 %"`. `detailInPeriod` becomes the string
  `"I perioden"`.
- Commits: Conventional Commits, `git commit -F <file>` with the message in the SDD workspace, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review focus

1. **A day turns while the span-free parts are kept:** the next answer reads them again (Task 2's "a new day" test).
2. **Two spans at once, one failing:** the other answers (Task 2).
3. **A bound of "0,5" or "0":** "0,5" is 50 øre; "0" is a bound of 0, not "no bound" (Task 9).
4. **A hash bound with øre where Fra > Til:** the hash reading gives no range, as today (Task 9).
5. **A failed load, then a new change:** the placeholder still has the last answer's box count (Task 4).

## Ruling on the second measurement

Spec §1.1 asks for the times after the change in the PR. The new server reaches the real add-on only after the merge,
the release and the house session (`CLAUDE.md` hard rule 4), so the times cannot be in this PR. Ruling: after the
house session has installed the release, Claude measures the same spans again (reading only) and writes the times in
a comment on #82; the PR description says so. If wrong, the cost is that the PR merges without the numbers.

## Task 2: Keep the span-free parts per day

Model: opus · Review: yes

**Files:** modify `addon/server/src/firefly/read.ts`, `addon/server/src/main.ts`, `addon/server/test/read.test.ts`,
`addon/server/test/client.test.ts` (the "lets the first error win" test asserts that the hanging requests were
aborted); create `addon/server/src/loader.ts`, `addon/server/test/loader.test.ts`;
docs `docs/decisions.md` (D49), `docs/architecture.md` (the cache line).

**Consumes:** Task 1.

**Produces:**
- `export interface SpanFree { accounts: WireAccount[]; categories: WireCategory[]; mainGroups: …; earliest: string |
  null; subscriptions: … }` in `read.ts`, the types `readSpendingData` destructures today.
- `export function readSpanFree(client: FireflyClient, settings: ReadSettings, today: string): Promise<SpanFree>`,
  under its own signal: `AbortSignal.timeout(settings.timeoutMs)` combined with its own first-failure controller, so
  one failed part aborts the other span-free reads, as today's `readSpendingData` does. No span's request aborts it.
- `readSpendingData(client, settings, range, context: { today; warn; spanFree?: () => Promise<SpanFree> })`: with
  `spanFree` it reads only the span's transactions under the span's signal and awaits `spanFree()`; without it, it
  calls `readSpanFree` itself. A failure of the span's transactions aborts only the span's read; a rejected
  `spanFree()` aborts the span's transactions read too.
- `export function createDataLoader(client: FireflyClient, settings: ReadSettings, now: () => Date, warn: (m: string)
  => void): DataLoader` in a new `addon/server/src/loader.ts`: it holds the answer cache (`ttlMs: 300_000, max: 20`,
  key `start|end`) and the span-free cache (`ttlMs: 300_000, max: 2`, key `today`), computes `today` once per call
  with `localToday(now())`, and passes `spanFree` to `readSpendingData`. `main.ts` calls it instead of building the
  cache itself.

- [ ] **Step 1: Write the failing tests** in `loader.test.ts`, driving `createDataLoader` with a counting fetch
  around the fake and a settable `now`:
  - `"two spans read in a row ask for the rules, categories, accounts and bills once"`.
  - `"a new day reads the span-free parts again"`.
  - `"after a failed read of the rules the next call asks for them again"` (the fake answers 500 once on the rules).
  - `"two spans at once, one whose transactions fail: the other answers with its data"`.
  - `"a failed span-free part aborts the other span-free reads"` (in `read.test.ts`, on `readSpanFree`).
  - `"without spanFree the answer is as before"` (an existing test's expectations, kept, in `read.test.ts`).
- [ ] **Step 2: Run** `npm test --workspace server`. Expected: the new tests fail.
- [ ] **Step 3: Implement** as in Produces. The main-group conflicts are still warned on each answer.
- [ ] **Step 4: Docs.** D49 in `decisions.md`, appended after D46; Tasks 9 and 14 insert D47 and D48 before it, so the

- [ ] **Step 5: Run** `npm run lint && npm test && npm run build`, and `node scripts/check-links.mjs`. Expected: pass.
