# Til overs – implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps are test-first.

**Goal:** the [Til overs spec](../specs/2026-11-04-left-over.md), in one PR that closes #173.

**Architecture:** three new options feed a new server computation over the same raw transactions `/api/data` reads.
`addon/server/src/firefly/left-over.ts` sorts each split into one bucket and sums the balance changes per month. A new
route, `/api/left-over`, answers it. The page fetches that route for the period. A new model,
`addon/web/src/model/left-over.ts`, rounds and signs the numbers. Those numbers feed a key-number card on the overview
and a new screen, `addon/web/src/screens/left-over.ts`, at `view=leftover`.

**Tech stack:** TypeScript; Hono on Node; Lit with Vitest, happy-dom and Testing Library.

**Spec:** [`docs/superpowers/specs/2026-11-04-left-over.md`](../specs/2026-11-04-left-over.md). Every task reads its
sections there; the plan does not repeat them.

## Review focus

1. **A month with no postings, inside the period.** The answer still has its month, with every amount 0 (Task 3
   test), and the table shows a row of zeros (Task 8 test).
2. **A period cut mid-month** (custom 15 Sep to 10 Nov):
   - The answer has the months 2026-11, 2026-10 and 2026-09. Only the days in the period count (Task 3 test).
   - A click on "sep." opens the whole of September (Task 8 test).
3. **A member's name used as a shop.** A withdrawal to the expense account "Anna" in a non-excluded category is
   Forbrug, not Tilbage, and the warning is logged once over two reads (Task 3 test).
4. **A year unit over a long period.** The period is "Alt", reaching back into 2025, and the unit is 2025. The card sums
   only 2025's months, and "Vis måneder →" still opens the view for the whole period (Task 7 test).
5. **A stale link.** `#view=leftover` with an answer whose `leftOver` is false shows the overview. The entry is
   replaced with a hash that has no `view` (Task 8 test).
6. **`/api/left-over` fails while `/api/data` works:**
   - On the overview the card is left out and the rest of the overview shows (Task 7 test).
   - In the view the page's error card shows, under the trail (Task 8 test).

## Task 3: The buckets and the months

Model: opus · Review: yes

**Files:**
- Create: `addon/server/src/firefly/left-over.ts`.
- Modify: `addon/server/src/firefly/normalise.ts`, `addon/server/src/firefly/read.ts`, `addon/shared/src/types.ts`.
- Test: `addon/server/test/left-over.test.ts`.

**Spec:** §3, §5 (matching), §6.2 (the answer's shape).

**Interfaces:**
- Produces, in `addon/shared/src/types.ts`:

  ```ts
  export interface LeftOverMember { name: string; paidIn: number; back: number }
  export interface LeftOverMonth {
    month: string; // YYYY-MM
    paidIn: number; back: number; members: LeftOverMember[];
    spending: number; savings: number; credit: number; other: number; change: number;
  }
  export interface LeftOverData {
    range: Period; today: string; hasSavings: boolean; hasCredit: boolean; months: LeftOverMonth[];
  }
  ```

  - `SpendingData` gains `leftOver: boolean`.
  - `months` runs newest first. It holds every calendar month that the range touches. `members` is by name and holds
    only members with an amount that is not zero.
- Produces, in `normalise.ts`: `spendingKind(split: WireSplit, mainGroupOf, excluded): Posting["kind"] | null`. It holds
  the test `toPostings` uses today, and `toPostings` calls it, so Forbrug and the overview cannot drift apart.
- Produces, in `read.ts`:
  - `ReadSettings` gains `members`, `savingsCategories` and `creditAccounts`, all `string[]`.
  - `SpanFree` gains `revenue: WireAccount[]` and `liabilities: WireAccount[]`, read in `readSpanFree` with
    `accounts?type=revenue` and `accounts?type=liabilities`.
  - `readSpendingData`'s context gains `groups?: () => Promise<WireGroup[]>`, used when given, as `spanFree` is.
  - It sets `leftOver` to true when some member name is a revenue account's name.
- Produces, in `left-over.ts`:
  - `leftOverMonths(groups: WireGroup[], range: Period, rules: LeftOverRules): LeftOverMonth[]`, pure.
    `LeftOverRules` is `{ members, savingsCategories, creditAccounts: ReadonlySet<string>; mainGroupOf; excluded;
    warn: (message: string) => void }`.
  - `readLeftOverData(client, settings, range, context: { today; warn; spanFree?; groups? }): Promise<LeftOverData>`.
    It reads like `readSpendingData`, under `firstFailure`.
  - `hasSavings` is true when a name in `savingsCategories` is a category in `SpanFree.categories`. `hasCredit` is true
    when a name in `creditAccounts` is in `SpanFree.accounts`.
- **The method:**
  - Read only splits of type `withdrawal`, `deposit` and `transfer`.
  - **Balances:** for each split, every side whose type is "Asset account" moves that account's balance: −amount for
    the source, +amount for the destination. The side is the credit line when its name is in `creditAccounts`, else a
    daily account. `credit` and `change` are the sums of those moves. A transfer between two household accounts thus
    nets out by itself.
  - **Buckets:** a split with exactly one asset side goes into the first bucket that takes it:
    1. `spendingKind` is not null: `spending` += amount for spending, −amount for a refund;
    2. a deposit whose `source_type` is "Revenue account" and whose `source_name` is a member: that member's `paidIn`;
    3. a withdrawal whose `destination_type` is "Expense account" and whose `destination_name` is a member: that
       member's `back`;
    4. `category_name` is in `savingsCategories`: `savings` += amount out, −amount in;
    5. otherwise `other` += amount in, −amount out.
  - **The warning:** log it when bucket 1 took a split that 2, 3 or 4 would have taken. The message is fixed and
    holds no amount, date or name. Task 4 makes it once per process.
  - `toOre` turns the wire amounts into øre.

- [ ] **Test:** `readLeftOverData` over the fake Firefly III, with a seed in the test file. Assert on the answer's
  months by name.
  - **Each bucket, as spec §7 lists them:**
    - a member's deposit with an excluded category is Ind;
    - a member's deposit with a non-excluded category is Forbrug, and the warning is logged;
    - money back to a member with an excluded category is Tilbage;
    - money back to a member with no category is Forbrug, and the warning is logged;
    - a member's deposit in one month and money back in the next;
    - a savings withdrawal and its return;
    - spending and a refund;
    - interest, and a deposit from a revenue account that is not a member, are Øvrigt;
    - a transfer between daily accounts changes nothing;
    - a transfer to and from the credit line is Kreditten;
    - a withdrawal from a daily account to the liability "Billån" lands where §3.2's order puts it.
  - **The sum rule:** an opening balance and a reconciliation (Task 1) change no amount. For every month,
    `change === paidIn − back − spending − credit − savings + other`.
  - **Forbrug** equals the sum of `/api/data`'s postings for the same range: `readSpendingData` over the same seed.
  - **Edges:**
    - a month cut by the range;
    - a posting after `today`;
    - a month with no postings (Review focus 1);
    - the custom range 15 Sep to 10 Nov (Review focus 2);
    - a member's name used as a shop (Review focus 3);
    - `hasSavings` and `hasCredit` with the options empty, with only an unknown name, with only the liability's name,
      and with a match;
    - `leftOver` in `readSpendingData`, true and false.
- [ ] **Run:** `npm test --prefix addon -- server/test/left-over.test.ts server/test/normalise.test.ts`. It must fail
  first, then pass. Then run the whole `npm test`.
