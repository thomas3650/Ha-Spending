# The shops with the most spending – implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps are test-first.

**Goal:** the [top shops spec](../specs/2026-11-02-top-shops.md), in one PR that closes #55.

**Architecture:** the server gains a small store for the hidden shops (a JSON file, one writer at a time) and two
routes, `GET` and `POST /api/hidden-shops`. The page gains a pure model `model/shops.ts`, a component `<hs-shops>`, a
fourth choice `card=shops` on the right card, and in `app.ts` the read of the hidden shops at start and the write on a
click.

**Tech stack:** TypeScript; Hono on Node; Lit with Vitest, happy-dom and Testing Library.

**Spec:** [`docs/superpowers/specs/2026-11-02-top-shops.md`](../specs/2026-11-02-top-shops.md). Every task reads its
sections there; the plan does not repeat them.

## Task 1: The server keeps the hidden shops

Model: opus · Review: yes

**Files:** create `addon/server/src/hidden-shops.ts`, `addon/server/test/hidden-shops.test.ts`; modify
`addon/shared/src/types.ts`, `addon/server/src/app.ts`, `addon/server/src/env.ts`, `addon/server/src/main.ts`,
`addon/server/test/env.test.ts`, `scripts/develop`, and every `createApp` caller, which gains a store on a temp path:
`addon/server/test/app.test.ts`, `data.test.ts`, `subscriptions.test.ts` and
`addon/server/test-integration/firefly.test.ts` (type-checked by `lint`, though the gates do not run it).

**Produces:** the shared types and the server names in Global constraints; spec §4.

- The store reads the file on every `read` and `set`; a missing file (`ENOENT`) is `[]`. A file that is not JSON or
  not `{"shops": string[]}` is `[]`, and logs `hidden shops: unreadable, treated as empty`. Any other read or write
  error rejects (the route answers 500 `internal`).
- `set` runs on a promise chain, so calls run one at a time in arrival order, each on what the one before wrote. It
  adds or removes the exact name, sorts with `localeCompare(…, "da")`, writes `{"shops": [...]}` to
  `<path>.<pid>.tmp` and `rename`s it onto the path. Hiding a new shop when 500 are hidden rejects with
  `HiddenShopsFull`. An unchanged list is not written.
- Routes, in `createApp`, before `app.all("/api/*")`:
  - `GET /api/hidden-shops` answers `HiddenShops` with `Cache-Control: no-store`.
  - `POST /api/hidden-shops`: the media type of `Content-Type` (before any `;`, trimmed, lower-cased) must be
    `application/json`, else 415 `unsupported`. The body as text must be at most 1024 bytes and parse to an object
    with exactly the keys `shop` and `hidden`; `shop` a string of 1 to 200 characters with no character below U+0020
    and no U+007F; `hidden` a boolean; else 400 `bad-request`. Then `store.set`; `HiddenShopsFull` is 409 `full`, any
    other error 500 `internal`. Success answers `HiddenShops` with `Cache-Control: no-store`.
  - Each error logs `POST /api/hidden-shops: <code>` (or `GET …`) through `options.log`, never the shop.
- `main.ts` builds the store on `env.hiddenShopsPath` with `console.error` as its log.
- `scripts/develop` exports `HA_SPENDING_HIDDEN_SHOPS="${HA_SPENDING_HIDDEN_SHOPS:-$PWD/local/hidden-shops.json}"`
  beside `HA_SPENDING_OPTIONS`.

## Task 2: The Butikker card

Model: opus · Review: yes

**Files:** create `addon/web/src/model/shops.ts`, `addon/web/src/components/shops.ts`, `addon/web/test/shops.test.ts`;
modify `state/view.ts` (`Card`, `CARDS`), `state/actions.ts` (`openShop`, `normalise`), `screens/overview.ts`,
`app.ts`, `i18n/da.ts`, `addon/web/test/view.test.ts`, `actions.test.ts`.

**Produces:**

```ts
export interface ShopRow { name: string; sum: number; share: number } // øre; whole per cent
export interface ShopList {
  visible: ShopRow[]; // net > 0, not hidden, by sum desc then name ("da")
  hidden: ShopRow[]; // net > 0, hidden, same order
  hiddenSum: number;
  noShop: number; // net of the base's postings with no shop
}
export type HiddenState = { kind: "loading" } | { kind: "ready"; shops: string[] } | { kind: "error" };
export function shopList(base: ClassifiedPosting[], hidden: ReadonlySet<string>): ShopList;
```

- `share` is `Math.round(sum / total(base) * 100)`, and 0 when `total(base)` is zero or less.
- `openShop(s, name)` is `{ ...chooseShop(s, name), card: "postings" }`. `normalise` turns `card=shops` into `bars`
  when no posting in `data.postings` has a shop.
- `Overview` gains properties `hiddenShops: HiddenState`, `shopsAll: boolean`, `shopsHidden: boolean`,
  `hiddenWriteFailed: boolean`. The switch shows `da.shops` ("Butikker") after Faste udgifter when any posting in
  `ctx.data.postings` has a shop. The title is `da.shops` at Alt forbrug and `da.shopsIn(levelName(level))` ("Butikker
  i Mad") otherwise. The base is `within(ctx.shown, ctx.chosen ?? ctx.timeline.period)`. With no posting in the base
  the body is `da.noSpending`. `this.fullScreen` means all rows and no "Vis alle".
- `<hs-shops>` takes `list: ShopList`, `chosen: string | null` (the chosen shop), `all: boolean`, `showHidden:
  boolean`, `canHide: boolean`, `limit: number | null` (10, or null in full screen). It renders spec §2 and §3 as an
  ordered list for the visible rows and a second list for shown hidden rows; the bar scale is the biggest `sum` among
  the rows it renders. Its buttons fire the four events in Global constraints.
- In this task `app.ts` passes `hiddenShops: { kind: "ready", shops: [] }` and holds `shopsAll` and `shopsHidden` as
  `@state` fields, toggled by the events, never in the hash. `shop-open` pushes `openShop`. `shop-hide` is wired in
  Task 3.
- `da` gains, exactly: `shops: "Butikker"`, `shopsIn: (name) => \`Butikker i ${name}\``, `hide: "Skjul"`,
  `hideShop: (name) => \`Skjul ${name}\``, `showShop: (name) => \`Vis ${name}\`` (the "Vis" button reuses the existing
  `da.show`),
  `showAllShops: (n: number) => \`Vis alle ${n}\``, `showFewer: "Vis færre"`,
  `showHidden: (n: number, sum: string) => \`Vis skjulte (${n} · ${sum})\``, `hideHidden: "Skjul skjulte"`,
  `noShop: (sum: string) => \`Uden butik: ${sum}\``, `noShops: "Ingen butikker at vise"`, `share: (p: number) =>
  \`${p} %\``. Each row's name button reuses `da.shopOption(name, kr(sum))` as its accessible name.

## Task 3: Hiding a shop from the page

Model: opus · Review: yes

**Files:** modify `addon/web/src/data/api.ts`, `app.ts`, `screens/overview.ts`, `components/shops.ts`, `i18n/da.ts`,
`addon/web/test/mount.ts`; tests in `addon/web/test/shops.test.ts`.

**Consumes:** Task 1's routes and types; Task 2's names.

- `loadHiddenShops()` GETs `api/hidden-shops` (relative) and resolves its `shops`; any failure rejects.
  `setHiddenShop(shop, hidden)` POSTs `api/hidden-shops` with `Content-Type: application/json` and
  `JSON.stringify({ shop, hidden })`, and resolves the answer's `shops`; any failure rejects.
- `app.ts` calls `loadHiddenShops()` once in `connectedCallback`, not waiting for `/api/data`, into a `@state`
  `hiddenShops: HiddenState` (starts `loading`). On `shop-hide` it calls `setHiddenShop`; on success it sets
  `hiddenShops` to the answer and `hiddenWriteFailed` to false; on failure `hiddenWriteFailed` true and the list as it
  was. No history entry.
- `da` gains, exactly: `fetching: "Henter …"`, `hiddenUnreadable: "Skjulte butikker kunne ikke hentes."`,
  `saveFailed: "Kunne ikke gemme. Prøv igen."` (`da.loading` is a different text and is not reused).
- The card: `loading` shows `da.fetching` ("Henter …") in place of the list; `error` shows every shop, `canHide`
  false, and `da.hiddenUnreadable` ("Skjulte butikker kunne ikke hentes."); `hiddenWriteFailed` shows
  `da.saveFailed` ("Kunne ikke gemme. Prøv igen.") under the title.
- `mount.ts`: the stubbed `fetch` sends a URL starting with `api/hidden-shops` to a second spy, `hidden`, and the rest
  to today's `fetch` spy, so the existing fetch counts stay. `MountOptions` gains
  `hidden?: (init: RequestInit | undefined) => Response | Promise<Response>`; the default keeps an in-memory list,
  answers GET with it, and applies a POST's body to it. `mount` returns `hidden` beside `fetch`.
